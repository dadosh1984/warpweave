## Why

Сейчас проверка соответствия кода спецификации происходит только один раз — перед архивированием готового изменения. Пока идёт работа, план и код могут незаметно расходиться, и это обнаруживается только в конце, когда переделывать уже дорого. Нужен механизм постоянной, а не разовой сверки.

## What Changes

- Добавить скилл `warpweave-drift-detection` — «Сторож», который запускается после каждой задачи в процессе `/ww-apply` и проверяет, не разошёлся ли код с утверждёнными spec-файлами
- Добавить команду `/ww:drift-check` для ручного запуска проверки
- Интегрировать дрифт-детекцию в пайплайн apply: после каждой завершённой задачи автоматически сверять код со specs
- При обнаружении расхождения: показать diff, предложить варианты (исправить код / обновить spec / продолжить с пометкой)
- Обновить README с описанием новой возможности

## Capabilities

### New Capabilities
- `drift-detection`: Скилл «Сторож» — автоматическая сверка кода со спецификациями после каждой задачи в процессе apply
- `drift-check-command`: CLI команда `/ww:drift-check` для ручного запуска проверки

### Modified Capabilities
- `apply`: Интегрировать дрифт-детекцию в пайплайн apply — после каждой завершённой задачи запускать проверку

## Impact

- Новый скилл: `skills/warpweave-drift-detection/SKILL.md`
- Новая команда: `/ww:drift-check`
- Модифицирован: `src/core/templates/workflows/apply.ts` — добавить хук дрифт-проверки после каждой задачи
- Модифицирован: `src/core/shared/skill-generation.ts` — добавить шаблон для нового скилла
- Нет новых зависимостей — использует существующие механизмы чтения spec-файлов и сравнения
- Без обратной несовместимости — дрифт-детекция работает поверх существующего пайплайна

## Ladder Decision

| Considered | Verdict |
|-----------|---------|
| YAGNI - skip entirely? | No — расхождение плана и код — реальный источник дефектов |
| Existing code reuse? | Yes — переиспользуем существующие парсеры spec-файлов и механизм контекста |
| Stdlib? | Yes — `node:fs` для чтения файлов, `node:path` для путей |
| Native platform? | No — кроссплатформенность через Node.js |
| New dependency? | No — все механизмы уже есть в проекте |
| One-liner? | No — требуется скилл, команда, интеграция в apply |
| Minimum | Скилл + команда + интеграция в apply пайплайн |
